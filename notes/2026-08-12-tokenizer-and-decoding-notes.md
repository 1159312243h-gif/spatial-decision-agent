# 2026-08-12 Tokenizer 与解码策略学习笔记

## 1. 先建立完整流程

大模型处理文字时，大致经过以下流程：

```text
原始文本
  ↓ Tokenizer 编码（Encode）
Token 序列
  ↓ 查词表
Token ID 序列
  ↓ 模型计算
下一个 Token 的 logits
  ↓ Softmax / Temperature
下一个 Token 的概率分布
  ↓ Greedy、Beam、Top-k 或 Top-p 等选择策略
选中的 Token ID
  ↓ Tokenizer 解码（Decode）
输出文本
```

这里有两个不同层面的“解码”：

1. **生成解码策略**：模型根据概率选择下一个 Token，例如 Greedy Search、Beam Search、Top-k Sampling。
2. **Tokenizer 的 decode 方法**：把最终的 Token ID 序列还原成人类能阅读的文本。

日常讨论“大模型 Decode 策略”时，通常指第一种；代码中的 `tokenizer.decode(ids)` 通常指第二种。

---

## 2. Tokenizer 是什么

### 2.1 全称与中文名

- **Tokenizer**：Tokenization 工具，也常译为**分词器**或**标记器**。
- **Tokenization**：**标记化**或**分词**。
- **Token**：**标记**、**词元**或**子词单元**。
- **Vocabulary / Vocab**：**词表**。
- **Token ID**：Token 在词表中对应的整数编号。
- **Encode**：**编码**，将文本转换为 Token ID。
- **Decode**：**解码**，将 Token ID 转回文本。

“分词器”这个中文名称容易让人误以为它只能按完整词语切分。现代大模型通常使用**子词分词**：一个 Token 可能是一个字、一个词、半个单词、标点、空格的一部分，甚至是一段字节序列。

### 2.2 为什么必须使用 Tokenizer

神经网络不能直接计算“生态保护红线”这些字符串，它只能处理数字。Tokenizer 负责建立文本和整数之间的映射：

```text
文本：生态保护红线
Token：['生态', '保护', '红线']       # 仅为示意，真实结果取决于模型
Token ID：[3812, 926, 7415]
```

模型处理的是 Token ID 对应的向量，不是原始字符串。

### 2.3 为什么不用“一字一 Token”或“一词一 Token”

**按字切分**：词表较小，但序列较长，模型需要自己学习字如何组成词。

**按完整词切分**：序列较短，但词表会非常大；新词、人名、拼写变化难以覆盖，容易产生词表外词。

**按子词切分**：在词表大小和序列长度之间折中。高频词可以作为一个 Token，低频词可以拆成多个已知子词或字节。

### 2.4 一个容易忽视的事实

Token 的划分由具体模型的 tokenizer 和词表决定。不能脱离具体模型断言“一汉字等于一个 Token”或“一英文单词等于一个 Token”。

## 3. BPE：Byte Pair Encoding

### 3.1 全称与中文名

- **BPE**：**Byte Pair Encoding**
- 中文通常译为：**字节对编码**

虽然名称中有 Byte，但最初的文本子词 BPE 实现不一定直接以原始字节作为初始符号。应区分传统 BPE 与后面的 Byte-level BPE。

### 3.2 核心思想

BPE 从较小的基本符号集合开始，反复合并训练语料中最频繁的相邻符号对，逐渐形成常见子词。

假设语料中存在：

```text
low low low lower lower newest
```

初始时可以拆成字符：

```text
l o w
l o w e r
n e w e s t
```

如果 `l + o` 是最频繁的相邻对，就将它合并成 `lo`；之后可能继续合并 `lo + w`，形成 `low`。

### 3.3 训练过程

1. 将训练文本拆成初始符号。
2. 统计所有相邻符号对的频次。
3. 合并频次最高的一对。
4. 将该合并规则加入词表或合并表。
5. 重新统计并继续合并，直到达到目标词表大小或合并次数。

每学习一个新的合并结果，通常会新增一个 Token。因此“每合并一次，词表大小增加 1”可以作为直观理解，但具体工具还可能包含特殊 Token、初始词表和实现差异。

### 3.4 优点与局限

优点：

- 常见词或词根可以成为较长 Token，减少序列长度。
- 生僻词可以拆成较小单元，缓解词表外问题。
- 算法直观、训练和编码效率较高。

局限：

- 合并依据主要是局部频次，不直接表达语义。
- 基于字符的多语言方案需要准备覆盖字符，Unicode 字符范围很大。
- 训练语料不同，学到的合并规则也会不同。

## 4. BBPE：Byte-level Byte Pair Encoding

### 4.1 全称与中文名

- **BBPE**：通常指 **Byte-level Byte Pair Encoding**
- 中文可译为：**字节级字节对编码**

### 4.2 它解决什么问题

字符级 BPE 如果想覆盖多种语言、符号和表情，需要很大的基础字符集合。BBPE 先把文本按 UTF-8 转换成字节，再以有限的字节值作为基础单位。

一个字节只有 256 种可能值，因此基础符号集合可以覆盖任意能编码成字节的文本，不需要事先把所有 Unicode 字符都放进初始词表。

### 4.3 重要纠正

“两个字节合并就可以表示 Unicode”并不准确。

UTF-8 中：

- 常见 ASCII 字符通常占 1 个字节。
- 部分字符占 2 个字节。
- 常见中文字符通常占 3 个字节。
- 部分表情或扩展字符可能占 4 个字节。

例如一个中文字符可能先变成 3 个 UTF-8 字节。BBPE 可以通过多轮 BPE 合并，把常见的 3 字节序列，乃至多个字符组成的高频序列，逐渐合并成一个 Token。

### 4.4 核心优势

- 理论上可以表示任意 UTF-8 文本，减少未知字符问题。
- 初始集合固定且较小，适合多语言文本。
- 能处理表情、特殊符号和罕见字符。

### 4.5 可能的问题

- 对训练语料中很少出现的中文或特殊字符，可能拆成多个字节 Token，导致序列变长。
- Token 边界不一定符合人类看到的字符或词语边界。
- 单独查看某个字节 Token，往往没有直观语义。

## 5. WordPiece

### 5.1 全称与中文名

- **WordPiece**：通常直接称为 **WordPiece 子词算法**或**词片模型**。
- 它曾广泛用于 BERT 系列 tokenizer。

### 5.2 与 BPE 的共同点

两者都从较小单元出发，通过合并形成更大的子词单元，也都在词表大小和序列长度之间做折中。

### 5.3 与 BPE 的关键差别

BPE 通常优先合并**出现次数最多**的相邻 pair。WordPiece 常用一种与概率提升相关的评分思想选择 pair。常见教学近似公式为：

```text
score(A, B) = count(AB) / (count(A) × count(B))
```

其中：

- `count(AB)`：A 和 B 相邻出现的次数。
- `count(A)`、`count(B)`：A、B 各自出现的次数。

如果一个 pair 经常一起出现，但两个组成部分单独并不常见，它的得分可能较高。这表示 A 与 B 之间结合得比较紧密。

### 5.4 如何理解“优先合并不太频繁的单 Token pair”

这个说法不够完整。真正关注的不是“两个 Token 越罕见越好”，而是：

> pair 一起出现的频率，相对于它们各自独立出现的频率是否足够高。

如果 A 和 B 都极常见，即使 `AB` 出现次数很高，可能只是偶然相邻；分母会抑制它的得分。相反，两个不太常见的子词如果大多数时候都绑定出现，它们的组合可能更值得进入词表。

### 5.5 WordPiece 编码示意

BERT 风格的 WordPiece 常用 `##` 表示一个子词不是词的开头：

```text
playing → play + ##ing
```

这只是特定实现的显示方式，不是所有子词算法都使用 `##`。

### 5.6 注意

公开资料常用上述公式解释 WordPiece，但不同库的训练实现可能有差异。核心记忆应是：BPE 偏向最高频 pair，WordPiece 偏向能更好提升语言模型概率的 pair。

## 6. Unigram Language Model

### 6.1 全称与中文名

- **Unigram Language Model**：**一元语言模型**
- 在 tokenizer 语境中通常简称 **Unigram** 或 **Unigram 分词模型**。

### 6.2 与 BPE 的方向相反

- BPE：从小词表开始，不断**增加和合并** Token。
- Unigram：从一个很大的候选词表开始，不断**删除**不重要的 Token。

### 6.3 基本概率思想

Unigram 假设一个分词结果中的各 Token 独立出现。一种切分 `x = (x1, x2, ..., xn)` 的概率可直观写为：

```text
P(x) = P(x1) × P(x2) × ... × P(xn)
```

为了避免很多小概率相乘造成数值问题，实际常用负对数似然损失：

```text
Loss(x) = -Σ log P(xi)
```

对同一句话可能存在多种切分方式，算法会寻找概率较高、损失较小的切分。

### 6.4 如何删减 Token

不能只看 Token 出现次数。常见思路是：

1. 先用当前大词表对整个语料进行概率建模。
2. 暂时移除某个候选 Token。
3. 让受影响的文本改用其他 Token 切分。
4. 重新估计语料损失会增加多少。
5. 优先删除使总损失增加较少的 Token。
6. 每轮删除一批，再重新训练概率，直到接近目标词表大小。

“删除使 loss 增加最少的 Token”是正确的直观理解，但实际实现通常为提高效率而批量剪枝，而不是每轮只删一个并完整重算所有内容。

### 6.5 为什么有些 Token 不能删

如果删除某些基本字符或字节后，部分文本再也无法被切分，模型就失去完整覆盖能力。因此实现中通常保留用于覆盖所有输入的必要基本单元，以及特殊 Token。

### 6.6 优点

- 可以在多种候选切分中选择概率更高的结果。
- 支持 Subword Regularization 等训练技巧：训练时采样不同合理切分，增强模型鲁棒性。
- 词表剪枝具有明确的概率目标。

## 7. SentencePiece

### 7.1 全称与中文名

- **SentencePiece**：常译为**句片段分词器**，实际使用中通常直接称 SentencePiece。
- 它是一个 tokenizer 训练和编码工具，不是与 BPE、Unigram 完全同层级的单一算法。

### 7.2 它与其他算法的关系

SentencePiece 常见可训练模型包括：

- **BPE** 模型。
- **Unigram** 模型。

需要纠正的是：不能简单说“SentencePiece 可以使用 BBPE”。SentencePiece 可以处理原始 Unicode 文本并训练 BPE 或 Unigram；Byte-level BPE 通常指另一类明确以字节为基础符号的实现。具体是否字节回退或如何处理未知字符，还取决于 SentencePiece 的配置。

### 7.3 为什么不依赖空格分词

很多传统英文 tokenizer 先按空格切单词，但中文、日文等语言不能依赖空格。SentencePiece 直接把原始文本当作符号序列训练，统一处理不同语言。

### 7.4 `▁` 符号是什么

SentencePiece 通常先把空格替换为可见的特殊符号 `▁`（U+2581，Lower One Eighth Block），使空格信息也能参与分词并被还原。

示意：

```text
原文：Hello world
内部表示：▁Hello▁world
```

这样模型能区分一个子词出现在词首还是词中，并在 decode 时恢复空格。

### 7.5 优点

- 可直接处理原始文本，不依赖语言特定的预分词规则。
- 适合中文、英文及多语言场景。
- 编码和解码通常是可逆或接近可逆的。
- 同一工具可以训练 BPE 或 Unigram 模型。

---

## 8. 五个概念的关系

| 名称 | 类型 | 核心动作 | 起点 |
|---|---|---|---|
| BPE | 子词词表学习算法 | 反复合并高频相邻 pair | 小词表 |
| BBPE | 字节级 BPE | 从字节开始，再反复合并 | 256 种字节值及特殊符号 |
| WordPiece | 子词词表学习算法 | 按概率提升类得分合并 pair | 小词表 |
| Unigram | 概率型子词模型 | 删除对语料损失影响较小的 Token | 大候选词表 |
| SentencePiece | tokenizer 工具/框架 | 直接处理原始文本，可训练 BPE 或 Unigram | 取决于所选模型与配置 |

一句话记忆：

> BPE 和 WordPiece 是“从小到大做合并”，Unigram 是“从大到小做删减”，BBPE 把 BPE 的基础单元换成字节，SentencePiece 是承载 BPE 或 Unigram 等模型的通用工具。

## 9. Decode 是什么

### 9.1 全称与中文名

- **Decode / Decoding**：**解码**。
- **Autoregressive Decoding**：**自回归解码**。
- **Logits**：模型输出的、尚未归一化的分数，也常译为**逻辑值**。
- **Softmax**：将 logits 转为总和为 1 的概率分布的函数，通常保留英文名。
- **Sampling**：**采样**。

### 9.2 自回归生成过程

大模型通常一次只决定下一个 Token：

```text
输入：建设项目
模型预测下一个 Token 的概率
选择：“选址”

新输入：建设项目选址
再次预测下一个 Token
选择：“需要”

不断重复，直到遇到停止 Token 或达到长度限制。
```

Greedy、Beam、Top-k、Top-p 的差别，就是每一步如何从候选 Token 中作出选择。

## 10. Greedy Search：贪心搜索

### 10.1 全称与中文名

- **Greedy Search**：**贪心搜索**。

### 10.2 原理

每一步都选择当前概率最高的 Token：

```text
A：0.60
B：0.25
C：0.15
```

Greedy 一定选择 A。

### 10.3 优点

- 速度快，实现简单。
- 同一输入通常产生确定性较强的结果。
- 适合较短、答案明确的生成任务。

### 10.4 局限

它只看当前一步的最高概率，不能保证整段序列的联合概率最高。当前最好的选择可能让后续选择变差，这就是所谓“局部最优不等于全局最优”。它也可能产生重复、单调的文本。

---

## 11. Beam Search：束搜索

### 11.1 全称与中文名

- **Beam Search**：**束搜索**或**集束搜索**。
- **Beam Width / Beam Size**：**束宽**，即每一步保留的候选序列数量。

### 11.2 原理

假设 `beam_size=2`，第一步不只保留概率最高的 A，还保留第二名 B。下一步分别扩展 A、B，再从所有新序列中保留总得分最高的两条，重复直到结束。

它比较的是候选**序列**，而不只是单个 Token。序列得分通常基于各步对数概率之和，还可能加入长度惩罚，避免一味偏好短序列。

### 11.3 优点

- 比 Greedy 探索更多路径，更可能找到整体概率高的序列。
- 常用于机器翻译、语音识别等偏向单一准确答案的任务。

### 11.4 局限与纠正

Beam Search 并不是主要用来“平衡准确率和多样性”。它通常追求高概率序列，束宽变大时输出反而可能更相似、更保守。它计算量更大，也不保证找到真正的全局最优。

对于开放式聊天，Beam Search 可能生成模板化或重复文本，因此现代聊天模型更常结合采样策略。

---

## 12. Top-k Sampling：Top-k 采样

### 12.1 全称与中文名

- **Top-k Sampling**：**前 k 采样**或 **Top-k 采样**。

### 12.2 原理

每一步只保留概率最高的 k 个 Token，去掉其他候选，再对保留候选重新归一化并随机采样。

例如 `k=3`：

```text
A：0.50
B：0.25
C：0.15
D：0.06
E：0.04
```

只从 A、B、C 中抽取，D、E 被排除。并不是永远选 A。

### 12.3 k 的影响

- `k=1` 时基本等价于 Greedy。
- k 较小：输出更稳定，但可能单调。
- k 较大：候选更多、更有创造性，也更可能选到不合适的低概率 Token。

### 12.4 局限

固定 k 不考虑概率分布的形状。如果某一步只有两个 Token 很合理，`k=50` 会纳入许多差候选；如果概率分布很平坦，`k=5` 又可能过早删掉合理候选。

---

## 13. Top-p Sampling：核采样

### 13.1 全称与中文名

- **Top-p Sampling**：**Top-p 采样**。
- **Nucleus Sampling**：**核采样**。

### 13.2 原理

将 Token 按概率从高到低排列，选取累计概率达到阈值 p 的最小候选集合，然后在这个集合中重新归一化并随机采样。

假设 `p=0.9`：

```text
A：0.50，累计 0.50
B：0.25，累计 0.75
C：0.15，累计 0.90
D：0.06，累计 0.96
```

候选集合为 A、B、C，再从中随机采样。

### 13.3 为什么说它能自适应

- 概率集中时，少数几个 Token 就能达到 p，候选集自动变小。
- 概率分散时，需要更多 Token 才能达到 p，候选集自动变大。

因此它比固定 k 更能适应每一步概率分布的变化。

### 13.4 p 的影响

- p 较小：更保守、更稳定。
- p 较大：更多样，也会引入更多低概率候选。
- `p=1` 通常意味着不通过 Top-p 删除候选，但仍可能受其他规则影响。

## 14. Temperature：温度参数

### 14.1 它不是独立的搜索算法

Temperature 更准确地说是**概率分布调节参数**，通常在 Greedy 或采样前缩放 logits：

```text
P(token_i) = softmax(logit_i / T)
```

其中 `T` 是 Temperature。

### 14.2 为什么除以 T 会改变随机性

- `T < 1`：logits 的差距被放大，最高概率 Token 更突出，分布更尖锐。
- `T > 1`：logits 的差距被缩小，各候选概率更接近，分布更平坦。
- `T → 0`：趋近只选择最高概率 Token；实际 API 对 0 的处理由实现决定。

### 14.3 一个数值直觉

假设两个 logits 是 2 和 1：

- `T=0.5` 时变成 4 和 2，差距扩大。
- `T=2` 时变成 1 和 0.5，差距缩小。

经过 Softmax 后，前者更确定，后者更随机。

### 14.4 与 Top-k、Top-p 的关系

典型采样流程可以是：

```text
logits
  ↓ Temperature 调整
概率分布
  ↓ Top-k / Top-p 截断候选
重新归一化
  ↓ 随机采样
下一个 Token
```

不同推理框架的具体处理顺序可能不同，但 Temperature 与 Top-k/Top-p 可以组合使用。

### 14.5 重要边界

Temperature 低不等于事实正确，Temperature 高也不等于模型更聪明。它改变的是分布和随机性，不能代替 RAG、GIS 计算、规则校验或 Pydantic 校验。

## 15. 解码策略对比

| 方法 | 是否随机 | 候选方式 | 适合场景 | 主要问题 |
|---|---:|---|---|---|
| Greedy | 否 | 每步只选概率最高者 | 简短、确定性任务 | 容易局部最优、重复 |
| Beam Search | 通常否 | 保留多条高分序列 | 翻译、识别等目标较明确任务 | 计算量大、可能模板化 |
| Top-k | 是 | 只在固定 k 个高概率 Token 中采样 | 控制候选数量的生成 | 固定 k 不适应分布变化 |
| Top-p | 是 | 在累计概率达到 p 的最小集合中采样 | 开放式对话和文本生成 | p 太高可能引入差候选 |
| Temperature | 本身不是采样 | 调整概率分布尖锐程度 | 与上述方法组合 | 不能保证事实或格式正确 |

---

## 16. 当前选址合规 Agent 应如何选择

### 16.1 任务拆分和合规说明

目标是稳定、可审查、少发挥。通常倾向：

- 较低 Temperature。
- 较保守的 Top-p。
- 明确的 System Prompt。
- 使用 Pydantic 校验结构化输出。
- 缺失数据明确返回“需要补充或核实”。

具体参数必须以公司接口实际支持情况和测试结果为准，不能仅凭通用经验宣称已完成。

### 16.2 为什么参数不能代替验证

即使采用 Greedy 或极低 Temperature，模型仍可能：

- 输出不存在的政策条款。
- 遗漏必填字段。
- 返回非法 JSON。
- 对空间叠加面积作错误推断。

因此项目仍需：

- Pydantic：验证输出结构和字段类型。
- GIS/PostGIS 工具：完成空间关系和面积计算。
- 规则引擎：执行确定性合规判断。
- 测试：覆盖非法 JSON、字段缺失和 API 异常。

## 18. 闭卷复述模板

### 18.1 Tokenizer 部分

> Tokenizer 负责把原始文本编码成模型能够处理的 Token ID，并在生成结束后把 ID 解码回文本。BPE 按频次从小词表逐步合并，WordPiece 按概率提升类得分合并，Unigram 从大候选词表中删除对损失影响较小的 Token。BBPE 从 UTF-8 字节出发解决多语言字符覆盖问题，SentencePiece 则是能直接处理原始文本并训练 BPE 或 Unigram 的通用工具。

### 18.2 Decode 部分

> 自回归模型每次预测下一个 Token。Greedy 每步选概率最高者；Beam 同时保留多条高分序列；Top-k 在固定数量的高概率候选中采样；Top-p 在累计概率达到 p 的动态候选集合中采样；Temperature 通过缩放 logits 改变概率分布的尖锐程度，本身不是事实校验机制。

## 20. 最低验收答案

- **Tokenizer**：文本与 Token ID 之间的编码、解码组件。
- **BPE**：不断合并最高频的相邻符号对。
- **BBPE**：从字节开始做 BPE，基础集合小且可以覆盖任意 UTF-8 文本。
- **WordPiece**：偏向合并能更好提升语言模型概率的相邻单元。
- **Unigram**：从大词表开始，优先删除使语料损失增加较少的 Token。
- **SentencePiece**：直接处理原始文本的 tokenizer 工具，可训练 BPE 或 Unigram。
- **Greedy**：每步选择最高概率 Token。
- **Beam**：每步保留若干条高分候选序列。
- **Top-k**：在固定 k 个高概率候选中采样。
- **Top-p**：在累计概率达到 p 的动态候选集合中采样。
- **Temperature**：缩放 logits 以调节概率分布和随机性，不是独立的事实校验方法。
