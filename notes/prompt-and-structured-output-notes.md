# Prompt 与结构化输出学习笔记

## 1. 三个概念先分清

### Prompt 模板

Prompt 模板是带有固定规则和可替换变量的提示词结构。它把稳定不变的要求与每次变化的用户数据分开。

```python
PROMPT_TEMPLATE = """
请从下面的选址需求中提取字段：

{requirement}

只返回约定的 JSON 字段，不要编造缺失信息。
"""

prompt = PROMPT_TEMPLATE.format(requirement=user_requirement)
```

- 固定部分：任务、边界、字段、输出规则。
- 变量部分：本次用户输入 `requirement`。
- 作用：减少重复拼接，使不同请求遵守相同规则，也方便测试和版本管理。
- 边界：模板能提高一致性，但不能保证模型一定遵守规则。

### Few-shot

Few-shot 是在 Prompt 中给模型少量“输入与正确输出”的示例，让模型模仿示例中的任务判断、字段名称和格式。

### 结构化输出

结构化输出是让模型按照事先定义的数据结构返回结果，例如 JSON 对象，而不是自由文本。随后程序再使用 Pydantic 检查字段、类型和约束。

```text
自然语言需求
→ Prompt 模板与示例
→ 模型返回 JSON 文本
→ JSON 解析
→ Pydantic 校验
→ 可信的 Python 对象，或明确失败
```

必须注意：模型“看起来返回了 JSON”，不等于已经通过结构化校验。

## 知识卡 1：Zero-shot 与 Few-shot

### 英文全称与中文名

- **Zero-shot Prompting**：零样本提示。不提供示例，只描述任务和规则。
- **One-shot Prompting**：单样本提示。提供一个完整示例。
- **Few-shot Prompting**：少样本提示。提供少量完整示例。

### Zero-shot 示例

```text
从用户需求中提取 project_type、land_area_hectares、
candidate_sites 和 review_items，只返回 JSON。

用户需求：计划建设一个占地 30 公顷的物流园，比较 A01 和 B01。
```

模型只依靠任务说明理解字段。

### Few-shot 示例

```text
示例输入：
建设一个 20 公顷的商场，候选地块为 C01，检查交通条件。

示例输出：
{
  "project_type": "shopping_mall",
  "land_area_hectares": 20,
  "candidate_sites": ["C01"],
  "review_items": ["交通条件"]
}

现在处理：
计划建设一个占地 30 公顷的物流园，比较 A01 和 B01，
检查生态保护红线和永久基本农田。
```

### Few-shot 为什么有用

- 示例把抽象要求变成可模仿的具体格式。
- 可以展示项目类型如何标准化，例如“物流园”映射为 `logistics_park`。
- 可以展示缺失信息如何处理，避免模型擅自补全。
- 可以稳定字段名、数组形式和枚举值。

### 示例设计原则

- 示例必须正确，错误示例会被模型模仿。
- 示例应覆盖容易混淆的边界，而不是堆很多相似例子。
- 输入和输出必须成对出现。
- 示例中的字段必须与 Pydantic 模型一致。
- 不要在示例里放真实密钥、隐私数据或未经核实的合规结论。

### 如何选择

- 任务简单、字段直观：先用 Zero-shot。
- 输出经常偏离格式或分类容易混淆：增加 Few-shot。
- Few-shot 仍不稳定：增加程序校验、失败处理和评测，不能只继续堆示例。

### 一句话记忆

> Zero-shot 只告诉模型规则，Few-shot 还给模型少量标准答案做参考，但两者都不能替代 Pydantic 校验。

## 知识卡 2：输出约束与结构化输出

### 输出约束是什么

输出约束是对模型返回结果规定明确边界，例如：

- 只允许固定字段。
- 字段类型必须正确。
- 枚举值只能来自允许集合。
- 列表不能为空或最多包含若干项。
- 缺少的信息使用 `null`、空列表或 `missing_fields` 表示。
- 不输出 Markdown 代码块和额外解释。

### 三层约束

#### 第一层：Prompt 约束

```text
只返回一个 JSON 对象，不要使用 Markdown 代码块，
不要输出解释，不要编造缺失字段。
```

这是自然语言要求，能改善结果，但模型仍可能不遵守。

#### 第二层：JSON 语法解析

程序使用 JSON 解析器检查返回内容是否是合法 JSON。它只能判断语法，不能判断业务字段是否正确。

#### 第三层：Pydantic 语义校验

Pydantic 检查：

- 必填字段是否存在。
- 字符串、数字和列表类型是否正确。
- 数值是否满足 `gt=0` 等范围约束。
- 空字符串是否应该拒绝。
- 未声明字段是否应该忽略或拒绝。

### 为什么要定义 Pydantic 对象

如果业务代码直接读取模型返回的任意字典，字段拼写或类型变化可能直到运行很深的位置才报错。Pydantic 可以在数据进入业务逻辑前建立清晰边界。

```python
requirement = SiteSelectionRequirement.model_validate_json(model_text)
```

成功时得到类型明确的 Python 对象；失败时抛出可捕获的校验异常。上面只是明天的目标调用形式，今天尚未接入模型返回值。

### 当前项目的结构化边界

今天只建立 `SiteSelectionRequirement` 模型骨架，用于描述：

- `project_type`：项目类型。
- `land_area_hectares`：占地面积，可缺失，但出现时必须大于 0。
- `candidate_sites`：候选地块标识列表。
- `review_items`：需要检查或比较的事项。

它是“自然语言选址需求的结构化表示”，不是合规审查结果，也不是法定审批结论。

### 一句话记忆

> Prompt 负责要求模型按格式回答，JSON 解析负责检查语法，Pydantic 负责检查字段和类型，三者职责不同。

## 知识卡 3：非法 JSON 与失败处理

### 什么是非法 JSON

JSON 必须符合严格语法。下面都可能导致解析失败：

```text
```json                  # 多了 Markdown 围栏
{"project_type": "物流园"}
```

{'project_type': '物流园'}  # 使用了单引号

{"project_type": "物流园",} # 最后多了逗号

这是结果：{"project_type": "物流园"} # JSON 前有解释文字
```

标准 JSON 的属性名和字符串必须使用双引号，不能带注释，也不能有尾随逗号。

### 合法 JSON 也可能业务不合法

下面在语法上是合法 JSON，但不一定能通过 Pydantic：

```json
{
  "project_type": "logistics_park",
  "land_area_hectares": -30,
  "candidate_sites": "A01",
  "review_items": []
}
```

问题包括：

- 面积为负数。
- `candidate_sites` 应该是列表，却给了字符串。
- 如果业务规定必须有审查事项，空列表也应被拒绝。

因此必须区分：

```text
非法 JSON：语法无法解析
校验失败：JSON 能解析，但字段、类型或取值不符合模型
业务失败：结构合法，但缺少继续执行所需的真实数据
```

### 正确的失败路径

```text
收到模型文本
→ 尝试解析并校验
→ 成功：返回 Pydantic 对象
→ 失败：记录不含密钥和敏感数据的错误摘要
→ 必要时执行有限次数重试或返回明确错误
→ 不把未校验字典传给 GIS、规则引擎或数据库
```

### 不推荐的“修复”方式

- 不要使用 `eval()` 解析模型文本，它可能执行恶意代码。
- 不要用大量字符串替换盲目修补 JSON，容易掩盖真实错误。
- 不要捕获异常后返回一个看似正常的空对象，会让下游误以为解析成功。
- 不要无限重试，会增加成本并可能重复失败。
- 不要把完整请求、响应或 API Key 打进日志。

### 明天要测试的失败场景

- 模型返回合法且字段完整的 JSON。
- 返回 Markdown 代码围栏。
- 返回单引号或尾随逗号导致非法 JSON。
- 缺少必填的 `project_type`。
- `land_area_hectares` 为负数或错误字符串。
- `candidate_sites` 不是列表。
- 模型返回空内容。

### 一句话记忆

> 非法 JSON 是语法问题，Pydantic 失败是结构和类型问题；两者都必须明确报错，不能让未验证内容进入后续业务流程。

## Prompt 模板的项目示例

下面是明天可继续实现的模板草案，不代表今天已经接入模型解析：

```python
REQUIREMENT_EXTRACTION_PROMPT = """
你需要从建设项目选址需求中提取结构化字段。

字段：
- project_type：项目类型；
- land_area_hectares：占地面积（公顷），未提供时为 null；
- candidate_sites：候选地块编号列表；
- review_items：需要比较或检查的事项列表。

规则：
1. 不得编造用户没有提供的信息；
2. 只返回一个 JSON 对象；
3. 不要使用 Markdown 代码块；
4. 不要输出 JSON 以外的解释。

用户需求：
{requirement}
"""
```

实际使用时，用户输入应作为数据插入明确位置，不能允许用户文本改写系统级边界。Prompt 模板仍需配合 Pydantic、异常处理和固定测试集。
