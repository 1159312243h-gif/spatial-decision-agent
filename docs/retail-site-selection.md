# 门店选址能力说明

## 解决什么问题

门店选址场景帮助个人创业者或连锁运营人员比较一组明确的候选位置。用户选择门店类型后，系统自动生成相应的 POI 查询计划，并把交通便利度、潜在需求代理、互补业态和同业竞争组织成可追溯证据。

当前支持：

- `coffee_shop`：咖啡店；
- `convenience_store`：便利店；
- `shopping_mall`：商场，保留原建设项目场景；
- `logistics_park`：物流园，保留原建设项目场景。

咖啡店和便利店不是商场 Profile 的显示别名。它们拥有独立的查询类别、查询半径、指标权重、候选数据、空间图层、规则包和运行时。

## 两类门店如何区别

| 维度 | 咖啡店 | 便利店 |
|---|---|---|
| 核心需求代理 | 办公、居住 | 居住、办公与学校 |
| 交通半径 | 1,200 米 | 1,000 米 |
| 竞品 | 咖啡馆 | 便利店、超市 |
| 互补业态 | 餐厅、书店、购物中心 | 餐厅、医院、快递网点 |
| 其他环境 | 公园、文化场馆 | 停车场、加油站 |

同业竞争不是简单地“越多越好”。竞争组使用单独方向：

- 竞品数量越少，竞争得分越高；
- 最近竞品越远，竞争得分越高；
- 交通、需求代理和互补业态仍按设施更多或距离更近获得更高分。

所有原始数量、距离、归一化方向、权重和加权结果都会保留，便于解释分数为什么变化。

## POI 与客流的边界

POI 数量只表示设施分布，不能等同于真实客流。因此界面和模型使用以下表述：

- 交通便利度；
- 潜在需求代理指标；
- 竞争密度；
- 互补业态。

要形成可用于真实投资的客流和营收判断，还需要接入并校准手机信令或热力、地铁进出站量、订单或支付、历史门店销售、人口与办公规模、租金和空置率等授权数据。当前 Agent 不会从 POI 数量推断这些事实。

## Fixture 演示数据

四类项目各有 6 个候选，共 24 个候选位置；POI Fixture 包含 1,157 条记录和 30 个类别。数据用于验证多候选排序、竞争方向、证据链和异常处理，全部标记为合成来源。

门店规则包只产生 `review_required`，要求人工核验真实用地、租赁与经营许可，不会把合成空间条件输出成“可开店”结论。

## 在线自动加载

当 `SITE_SELECTION_POI_PROVIDER=auto` 时，有高德 Key 则使用高德，否则使用 Overpass。新增的书店、公园、便利店、超市和停车场均有受控 Overpass 标签映射。在线失败时允许显式回退 Fixture，但来源、失败类型与合成标记会进入证据审查。

## 面试时可以如何描述

这个 Agent 不是替用户拍板，而是把自然语言选址需求变成可执行、可审计的空间分析任务。LLM 负责理解和解释，GIS、POI 指标和规则引擎负责确定性计算。门店类型会改变查询计划和评分模型；每个分数都能回到原始 POI、距离、数据版本和规则依据。当前作品证明的是 Agent 编排和证据工程能力，真实商业上线仍需要授权客流、经营和成本数据校准。
